# Session retention

## Startup contract

Automatic maintenance is background work, not a prerequisite for startup. The session-start handler only schedules it; a busy agent defers the launch until `agent_settled`. After launch, work may overlap an agent run, so automatic discovery offers `/session-cleanup` in a notification rather than opening an approval dialog. The explicit command owns first approval; previously approved stores retain daily automatic cleanup.

The original operational READMEs describe the older startup approval dialog. Use the contract above for current startup behavior; preserve the existing daily schedule, pause state and explicit commands.

## Lifecycle safety

Queued timers are cancelled on shutdown or explicit maintenance. Explicit commands wait for already-running automatic cleanup, showing a waiting footer, then recheck lifecycle cancellation before acquiring their own locks; an aborted runtime must not open a delayed picker. Other interactive maintenance still fails closed rather than opening a second dialog. Running work holds the per-store lock and the shared registry gate, protecting every registered open session's family. Switches and forks across cooperating instances are blocked while maintenance runs. Shutdown aborts and drains the complete background task, registration and file work before the context can be replaced. Retain graph revalidation and filesystem safety checks even when optimizing scans.

## Active-session registration

`<agent-home>/session-retention/<pid>.json` records absolute session paths and the OS process start identity. Registration runs in the background in every mode, retrying gate contention until shutdown aborts it; only TUI mode schedules maintenance. The registry gate (`.registry.lock`) covers the entire maintenance transaction, including discovery and approval. Successful OS inventories are cached for at most one second during maintenance. Missing, malformed, inaccessible or mismatched registrations for recognized live Pi processes defer maintenance; dead-PID records are ignored without a heartbeat/idle timeout. Instances using another agent home cannot be verified and still require closing.

Before a resume, register both current and target paths under the gate (`targetSessionFile` on the host event). Import destinations may not exist yet; registration does not require opening the target. Keep pending targets if another extension cancels the switch: extra protection is safer than guessing whether replacement completed. The next session-start registration replaces them. Register the in-memory header's `parentSession` alongside the allocated current filename: an unsaved child may not be discoverable on disk yet. New/fork transitions retain current-family protection; shutdown leaves the last record intact through runtime replacement, and drains registration to prevent an old writer overwriting the new runtime's record. Never infer closed sessions from file age or a heartbeat timeout.

Lock owner metadata is synced to a `.lock-<uuid>.tmp` file before exclusive hard-link publication; never expose an empty owner record to a competing startup. Trash listing ignores these adapter-owned staging files. Registry and store locks fail closed after crashes. The error names the lock path; close all Pi processes before manually removing a stale lock. Updated idle windows can remain open, but launching a new process during maintenance still races the sampled process inventory. This extension cannot provide a native lock honored by unrecognized SDK hosts or external programs.

## Trash picker and advisory cache

Open the picker from freshly validated manifests and filename fallbacks before reading transcripts. Enrich names and first-prompt search text in the background; show indexing progress and metadata failures so incomplete search is visible. Preserve the query and selected family ID when choices update.

Render the list like session search: family rows grouped under folder headers for their originating project (the first segment of each manifest `original` path). Folder labels prefer a cached working directory over the raw encoded segment, and the selected family's folder stays fixed above the scrolling rows while inline headers skip the fixed copy. Navigation moves between families, never folder headers; empty states keep their explicit text.

`<trash>/.search-cache/<batch-id>.json` is disposable display/search metadata, never a source of paths, family membership, retention dates or mutation approval. Fingerprints include manifest membership and file identity, size, modification and change timestamps. Recheck identity around cache reads and transcript extraction; changed, replaced, missing or unsafe files get no stale display data. Bump the cache version when its schema or extraction/search semantics change. Keep cache records bounded, private and atomically published; cache read/write failures fall back to fresh indexing rather than blocking recovery.

Closing/selecting the picker or shutting down aborts indexing. Drain streams, cache work and the indexing task before releasing either lock or starting a restore; suppress late UI updates. Restore and purge retain fresh core validation. Remove associated cache entries after successful restore/purge; report cache-erasure failures without undoing completed session operations. Startup cleanup never indexes full transcripts.

## Read-only preview

Enter switches the same overlay from search to a session preview; Esc returns to the preserved search/selection. Ctrl+R requests whole-family restore from either view through the command's existing confirmation. Plain letters remain searchable. The preview's member switcher changes only the inspected session, not restore scope. Page keys scroll both views via `tui.select.pageUp`/`pageDown`; physical Home/End (matched with `matchesKey`, not a keybinding action) jump to the first/last family and the preview's top/bottom, leaving Ctrl+A/Ctrl+E for search-cursor movement.

Load excerpts only on demand. Revalidate the selected manifest through `getTrashBatch` and refuse changed membership before previewing or confirming restore. Preview readers open only validated stored paths, verify source identity around reads, and expose bounded first-request/current-branch user/assistant text; tool results, thinking, images and terminal escape sequences stay out. Limits in `preview.ts` bound excerpts and topology; oversized or unverifiable previews leave confirmed, freshly validated restore available. Preview never resumes a session, executes tools, writes transcripts or calls a model.

Compose preview bodies from Pi's `Markdown` and `getMarkdownTheme()` inside the existing `ScrollView`, with a separate renderer for each excerpt so clipped code fences cannot consume later messages. Put a muted vertical rail and two-column gap before every rendered body line, including blank lines and code; reserve the rail's width before Markdown wrapping. Keep bold `mdLink` (blue in Pi's built-in themes) `You` and bold `warning` (yellow by default) `Assistant` labels outside the rail. Use full-width ruled `FIRST REQUEST` and `RECENT MESSAGES` markers outside message bodies, with no user-message background. Rebuild themed children on host invalidation, retaining native Markdown caches during scrolling and search enrichment.

Keep the session title, muted project/member metadata and literal project path outside the scroll area. Derive Windows and POSIX project names independently of the host platform; left-truncate long paths by terminal columns so their suffix remains readable. Put the preview/excerpt-shortening notice in a fixed status strip separated from the transcript, above the restore/navigation hints. Loading/error text remains literal; reset fixed metadata and status on member changes so old details cannot appear while a new source loads or fails. Compact terminals prioritize transcript and controls while staying within width/height bounds. Transcript controls are sanitized before formatting.

Back/member changes abort superseded reads; stale completions cannot update the current view. Restore, disposal and shutdown abort all preview work. Drain every task, including superseded reads, alongside search indexing before releasing either lock or showing restore confirmation.

## Verification

Run `node --test packages/pi-session-retention/test/*.test.mjs` from the repository root. Startup tests use controlled timers and a gated real-store scan to assert non-blocking dispatch, idle deferral, lock ownership during shutdown and explicit approval. Fixtures stay in temporary directories; live retention approval can authorize moves and permanent purges, so interactive checks require an isolated agent home. `PI_NATIVE_RETENTION=1 node --test packages/pi-session-retention/test/native-search-cache.test.mjs` additionally exercises cache/preview I/O and dialog rendering inside an isolated real Pi host, without model calls or live session data.
